# How we work

Solo is still a team of roles. Wear one hat at a time. Write things down so future-you (and a hiring manager) can see the thinking.

## Roles, even when they are all you

| Hat | Job | Lives in |
|---|---|---|
| Creative manager | Feel, voice, what we will not become | `CREATIVE/` |
| Program manager | Sequence, status, “what is this week” | `PRESENT/`, `FUTURE/`, this file |
| Designer / engineer | Make the slice | `Gateaux/` |

Do not invent a fourth hat called “producer of documents.” If a doc does not change a decision or a build, cut it.

## Cadence

**Monday (15 min).** Read `FUTURE/this-week.md`. If last week’s “done when” failed, say so in `PRESENT/status.md` — do not silently roll it.

**Whenever you ship.** One bullet in `PAST/changelog.md`. If you chose a fork, one entry in `PAST/decision-log.md`.

**One playtest a week.** Friend or stranger. Log it. Desk-only weeks are allowed, but call them desk.

**Friday (15 min).** Retro, four lines, pasted into changelog or a dated note:

- Kept
- Cut
- Still wrong
- Next week’s one sentence

Templates: `templates.md`.

## Priority rule

Feel > content reorder > new systems.

If a task needs a new currency, a new language, or an AI call to succeed, it is not this week.

## Portfolio hygiene

When you show this folder in a hiring process:

1. `PRESENT/status.md` — you can see clearly
2. `CREATIVE/player-feel.md` — you can say no
3. `FUTURE/roadmap.md` — you can sequence
4. `PAST/decision-log.md` — you can remember why

Keep the writing specific. Fake Jira is worse than a short honest status.
